# Тэмдэглэх заавар (алтан стандарт: СА3, СА4)

Бүлэг 4-ийн туршилтад системийн үр дүнг **мэргэжилтний тэмдэглэгээтэй** харьцуулна. Энэ баримт нь
тэмдэглэгчид (Г.Нармандах, О.Мэнд-Амар) ижил дүрмээр, бие биеэсээ хамааралгүй тэмдэглэхэд зориулагдсан.
Хэрэгсэл: `backend/app/evaluation/` (`python -m app.evaluation --help`). Ерөнхий тойм: [DATA.md](DATA.md).

| Даалгавар | Тэмдэглэх зүйл | Утга | Хэмжүүр |
|---|---|---|---|
| СА3 | CLO × сургалтын элементийн хос бүр | `direct` / `partial` / `none` | P, R, F1; kappa |
| СА4 | CLO болон **үнэлгээний** элемент (лаборатори, бие даалт, шалгалт) бүрийн Блумын түвшин | 1–6 | macro-F1; kappa |

СА4-т лекцийг тэмдэглэхгүй: түвшний зөрүү (ФШ-12) зөвхөн үнэлгээнд хамаарна.

---

## 1. Ажлын дараалал

```bash
cd backend && source .venv/bin/activate
```

1. **Өгөгдөл оруулах.** 2–3 хичээлийн бодит CLO, сургалтын элементийг системд оруулна (CSV импорт).
   Эх баримтыг `data/private/`-д хадгална, git-д оруулахгүй.
2. **Загвар гаргах:**
   ```bash
   python -m app.evaluation export ӨС201 ПХ305
   ```
   `data/private/annotations/`-д `links_annotator_A.csv`, `links_annotator_B.csv`, `bloom_annotator_A.csv`,
   `bloom_annotator_B.csv` үүснэ. Мөрүүд санамсаргүй дараалалтай, **системийн санал, оноо, түвшин
   агуулаагүй** байна. Мөр бүрийн `split` (`dev` ≈30% / `test` ≈70%) нь θ сонгох ба эцсийн үнэлгээний хуваалт.
3. **Туршилтын тэмдэглэгээ (10–20 мөр).** Хоёулаа эхний 15 мөрийг бие даан тэмдэглээд, зөрүүг хэлэлцэж энэ
   зааврыг тодруулна. Зааврыг өөрчилсөн бол доорх «Өөрчлөлтийн бүртгэл»-д тэмдэглэнэ.
4. **Бүтэн тэмдэглэгээ.** A нь `*_annotator_A.csv`, B нь `*_annotator_B.csv`-г бөглөнө (Excel, Numbers,
   LibreOffice — UTF-8 CSV хэлбэрээр хадгална). Дуустал бие биеийнхээ файлыг харахгүй, ярилцахгүй.
5. **Тохироо шалгах:**
   ```bash
   python -m app.evaluation agreement links
   python -m app.evaluation agreement bloom
   ```
   Зорилт: **κ ≥ 0.61** («нэлээд», Landis & Koch). Доогуур бол зааврыг тодруулж, зөрүүтэй хэсгийг дахин тэмдэглэнэ.
   Эхний κ-г (дахин тэмдэглэхээс өмнөх) Бүлэг 4-т тайлагнана.
6. **Нэгтгэх:**
   ```bash
   python -m app.evaluation merge links
   python -m app.evaluation merge bloom
   ```
   `links_gold.csv`, `bloom_gold.csv` үүснэ. `disputed=1` мөрийн шошго хоосон байна — хамтдаа хэлэлцэж бөглөнө.
   Дахин `merge` хийхэд бөглөсөн шошго хадгалагдана.
7. **Үнэлэх:**
   ```bash
   python -m app.evaluation evaluate
   ```
   `data/private/annotations/results/`-д `results.md` (хүснэгтүүд), `results.tex` (Бүлэг 4-т оруулах),
   `curve_<арга>.csv` (P–R муруй), `results.json` бичигдэнэ. Embedding (А6) хэрэгжээгүй бол тухайн арга
   «боломжгүй» гэж гарна.

**Хэмжээ, хугацаа.** 3 хичээл × 6 CLO × 15 элемент ≈ 270 хос (СА3) ба ≈ 50 объект (СА4) — нэг хүнд 2–3 цаг.
Нэг суултаар бүгдийг хийхгүй, 45–60 минут тутамд завсарлана.

## 2. Ерөнхий зарчим

- **Зөвхөн бичигдсэн текстээр** дүгнэнэ. Хичээлийг хэрхэн заадгийг мэдэж байсан ч текстэд байхгүй зүйлийг таамаглахгүй.
- **Системийн үр дүнг харахгүй.** Тэмдэглэж дуустал матриц, санал, Блумын автомат түвшинг нээхгүй.
- Эргэлзвэл хамгийн боломжит шошгыг сонгоод `note` баганад шалтгааныг товч бичнэ. Шошгыг хоосон үлдээхгүй.
- Хоёр тэмдэглэгч ижил дүрэм хэрэглэх нь чухал — «зөв» хариултаас илүү **тууштай** байдал.

## 3. СА3: CLO ↔ сургалтын элемент

Асуулт: **«Энэ элемент энэ CLO-д хүрэхэд хэр шууд хувь нэмэр оруулах вэ (заах эсвэл үнэлэх)?»**

| Шошго | Хэзээ | Шалгах асуулт |
|---|---|---|
| `direct` | Элемент CLO-ийн **гол агуулгыг** зааж эсвэл үнэлж байна. CLO-д хүрсэн эсэхийг энэ элементээр харуулж болно. | Энэ элементийг хассан бол CLO-д хүрсэн эсэхийг шалгах/заах үндсэн хэсэг алга болох уу? → тийм |
| `partial` | Элемент CLO-ийн **нэг хэсэг**, эсвэл түүнд шууд хэрэглэгдэх суурь агуулгыг хамарна. | CLO-ийн зарим хэсэг л хамрагдаж байна уу, эсвэл CLO нь энэ элементийн гол зорилго биш үү? → тийм |
| `none` | Агуулгын хувьд холбоогүй, эсвэл зөвхөн ерөнхий салбар (жишээ нь хоёулаа «өгөгдлийн сан»-гийн тухай) давхцаж байна. | Ижил хичээлийн хоёр өөр сэдэв үү? → тийм |

### Дүрмүүд

1. **Сэдвийг дүгнэнэ, түвшинг биш.** Түвшний таарц СА4-ийн асуудал. «ER диаграмм зохиох» CLO ба «ER гэж юу вэ?»
   асуулт сэдвээрээ холбоотой → `direct` эсвэл `partial` (түвшний зөрүүг систем тусад нь илрүүлнэ).
2. **Лекц** ч гэсэн тэмдэглэнэ: CLO-ийн агуулгыг заадаг лекц → `direct`; хэсэгчлэн → `partial`.
3. **Нэг элемент олон CLO**-той `direct` байж болно (жишээ нь эцсийн шалгалт). Мөр бүрийг тусад нь дүгнэнэ.
4. **Ерөнхий элемент** (ирц, танилцуулга, давтлага) нь тодорхой CLO-ийн агуулга дурдаагүй бол `none`.
5. **Урьдчилсан мэдлэг:** элемент нь CLO-ийн өмнөх алхам бол (жишээ нь «SQL SELECT» ба «нийлмэл JOIN хүсэлт бичих»)
   `partial`; огт өөр ур чадвар бол `none`.
6. **Үг давхцах ≠ холбоо.** «өгөгдөл», «систем», «загвар» гэх мэт ерөнхий үг давхцсан ч агуулга өөр бол `none`.
   Эсрэгээр, өөр үгээр бичигдсэн ч утга нь ижил бол холбоотой (жишээ нь «нормчлол» ба «хэвийн хэлбэрт оруулах»).

### Жишээ

| CLO | Элемент | Шошго | Шалтгаан |
|---|---|---|---|
| Бодит асуудалд ER диаграмм зохиомжлох | Лаб 2: Номын сангийн ER диаграмм зохиох | `direct` | Гол агуулгыг шууд хэрэгжүүлнэ |
| Бодит асуудалд ER диаграмм зохиомжлох | Лекц 3: ER загвар, холбоосын төрлүүд | `partial` | Суурь ойлголтыг заана, зохиомжлох дадлага биш |
| Бодит асуудалд ER диаграмм зохиомжлох | Шалгалт: «Primary key гэж юу вэ?» | `partial` | Холбоотой ойлголт, CLO-ийн гол агуулга биш |
| SQL хүсэлт бичиж өгөгдөл боловсруулах | БД1: JOIN ашигласан 10 хүсэлт | `direct` | Гол агуулгыг үнэлнэ |
| SQL хүсэлт бичиж өгөгдөл боловсруулах | Лаб 2: ER диаграмм зохиох | `none` | Ижил хичээлийн өөр сэдэв |
| Хүснэгтийг нормчлолын түвшнээр шинжлэх | Шалгалт: «3NF хүртэл хэвийн болго» | `direct` | Өөр үгээр бичигдсэн ч ижил агуулга |

## 4. СА4: Блумын түвшин

Асуулт: **«Оюутан энэ үр дүнд хүрэх / энэ даалгаврыг гүйцэтгэхийн тулд ямар танин мэдэхүйн үйлдэл хийх ёстой вэ?»**
Шинэчилсэн Блумын ангилал (Anderson & Krathwohl, 2001):

| Түвшин | Нэр | Оюутан юу хийдэг | Ердийн үйл үг |
|---|---|---|---|
| 1 | Санах | Баримт, тодорхойлолтыг таних, эргэн санах | нэрлэх, жагсаах, тодорхойлох, «… гэж юу вэ?» |
| 2 | Ойлгох | Өөрийн үгээр тайлбарлах, жишээ гаргах, ангилах, хураангуйлах | тайлбарлах, жишээ гаргах, ялгааг хэлэх |
| 3 | Хэрэглэх | Мэдсэн журам, аргыг тодорхой нөхцөлд гүйцэтгэх | тооцоолох, хэрэгжүүлэх, (хүсэлт) бичих, ашиглах |
| 4 | Задлан шинжлэх | Бүрэлдэхүүн хэсэгт задлах, харьцуулах, шалтгаан, бүтцийг тодорхойлох | харьцуулах, шинжлэх, ялгаж ангилах, алдаа олох |
| 5 | Үнэлэх | Шалгуураар дүгнэх, сонголтоо үндэслэх | үнэлэх, үндэслэх, шүүмжлэх, аль нь илүүг сонгох |
| 6 | Бүтээх | Хэсгүүдийг нэгтгэн шинэ бүтээгдэхүүн, төлөвлөгөө, загвар гаргах | зохиомжлох, зохиох, хөгжүүлэх, төлөвлөх |

### Дүрмүүд

1. **Үйл үгээс илүү шаардлагыг харна.** «Тайлбарла» гэсэн ч шинэ нөхцөлд хоёр шийдлийг харьцуулахыг шаардвал 4.
   Толь бичигт суурилсан систем үүнийг алддаг тул энэ тохиолдлуудыг зөв тэмдэглэх нь туршилтад чухал.
2. **Олон үйлдэлтэй бол гол (дүгнэгдэх) үйлдлийн түвшин.** «ER диаграмм зохиож, тайлбарлах» → 6, учир нь гол
   бүтээгдэхүүн нь диаграмм. Туслах, бичгийн үйлдэл (тайлбар бичих) түвшинг бууруулахгүй.
3. **Шалгалтын асуулт:** асуултын шаардлагаар дүгнэнэ. Лекцээр яг ижил жишээг бодсоныг мэдэж байсан ч зөвхөн текстээр дүгнэнэ (2-р хэсгийн ерөнхий зарчим).
4. **Лаб, бие даалт:** даалгаврын эцсийн бүтээгдэхүүнээр. Бэлэн загвараар алхам дагаж хийх → 3; шинэ асуудалд өөрөө
   загвар гаргах → 6.
5. **CLO:** CLO-ийн үйл үг ихэвчлэн зорилгыг шууд илэрхийлдэг тул түүгээр эхлээд шалгаж, контекстоор баталгаажуулна.
6. **Хоёр түвшний хооронд эргэлзвэл** доод түвшнийг сонгож, `note`-д «2/3» гэх мэтээр бичнэ (хоёр тэмдэглэгч ижил
   чиглэлд шийдвэрлэснээр тохироо нэмэгдэнэ).

### Жишээ

| Текст | Түвшин | Шалтгаан |
|---|---|---|
| CLO: Өгөгдлийн сангийн үндсэн ойлголт, загваруудыг тайлбарлах | 2 | Тайлбарлах = ойлгох |
| CLO: Бодит асуудалд ER диаграмм зохиомжлох | 6 | Шинэ загвар бүтээх |
| Шалгалт: «Primary key гэж юу вэ?» | 1 | Тодорхойлолт санах |
| Бие даалт: SQL JOIN ашигласан 10 хүсэлт бичих | 3 | Мэдэх аргыг хэрэглэх |
| Шалгалт: «Өгөгдсөн хүснэгтийг 3NF хүртэл хэвийн болго» | 4 | Хамаарлыг задлан шинжилж хувиргах (нэгдүгээр тэмдэглэгээнд 3 гэж үзэх боломжтой — туршилтын шатанд тохирно) |
| Лаб: Хоёр индексийн стратегийг харьцуулж, тохирохыг үндэслэн сонгох | 5 | Шалгуураар дүгнэж сонгох |

## 5. Зөрүүг хэлэлцэх (gold.csv)

- `disputed=1` мөр бүрийг хамтдаа уншаад энэ зааврын дүрмээр шийднэ. Дүрэм хангалтгүй байвал дүрмийг нэмж,
  өмнөх ижил төрлийн мөрүүдийг ч дахин шалгана.
- Санал нийлэхгүй бол ахлах багш (удирдагч)-аас асууна. Шийдвэрийг `note`-д товч бичнэ.
- `label_A`, `label_B` баганыг өөрчлөхгүй — kappa эдгээрээр тооцогдоно.

## 6. Багануудын тайлбар

**links_\*.csv:** `pair_id` (CLO id–элемент id), `split`, `course`, `clo_code`, `clo_text`, `item_type`, `item_title`,
`item_text` (гарчиг + тайлбар + асуулт — систем яг энэ текстээр шинжилнэ), **`label`**, `note`.
Бөглөх: `direct` / `partial` / `none` (мөн `шууд` / `хэсэгчлэн` / `холбоогүй`, `d` / `p` / `n`-ийг хүлээн авна).

**bloom_\*.csv:** `obj_id` (`clo:<id>` эсвэл `item:<id>`), `split`, `course`, `kind`, `code`, `text`, **`level`** (1–6), `note`.
